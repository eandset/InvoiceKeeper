# Invoice Keeper — Система учёта и контроля регулярных платежей

**Invoice Keeper** — это комплексная платформа для отслеживания регулярных платежей, периодов оплаты и автоматической рассылки уведомлений. Система состоит из трех основных компонентов: бэкенд-сервиса на **.NET 10 (ASP.NET Core)**, веб-интерфейса на **React + Vite** и Telegram-бота на **aiogram 3**.

## ⚠️ КРИТИЧЕСКИ ВАЖНО: Различие токенов бота

В системе используются **ДВА разного типа токена** для Telegram-бота. Обратите особое внимание на их разграничение в конфигурации (`.env`):

1. **`BOT_TOKEN`** (Токен Telegram Bot API)
   - **Где берется:** Выдается BotFather в Telegram (начинается с цифр, например `1234567890:ABC...`).
   - **Для чего используется:** Нужен **только** самому боту для подключения к Telegram API (long polling), отправки сообщений в чат и чтения команд пользователей.
   - **Куда прописывается:** В конфигурацию бота (`tgbot/bot-aiogram/.env`).

2. **`BOT_SERVICE_TOKEN`** (Сервисный токен API бэкенда)
   - **Где берется:** Генерируется вами (произвольная секретная строка, например `bot-vefqwk3ymlrodng48azij1x07bus25cp`).
   - **Для чего используется:** Нужен для авторизации бота в бэкенд-системе. Бот передает его в заголовок `X-Service-Token` при каждом запросе к REST API (`/api/v1`). Это позволяет боту выполнять служебные запросы без прохождения процедуры стандартного входа под логином и паролем.
   - **Куда прописывается:** **И в `.env` бэкенда, и в `.env` бота** (значения должны СТРОГО совпадать!).

## 🔑 Важные архитектурные особенности

### 1. Матрица прав и авторизации
В бэкенде реализовано 3 типа субъектов:
* **Admin** — Полный CRUD над платежами и пользователями, ручной пересчёт просрочек. Аутентификация через JWT (`POST /api/v1/auth/login`).
* **User** — Просмотр данных, подтверждение факта оплаты периодов. Аутентификация через JWT.
* **Service (Бот)** — Выборка актуальных напоминаний и получение аналитики. Аутентификация через заголовок `X-Service-Token: <BOT_SERVICE_TOKEN>`.

### 2. Идемпотентность и защита от повторных уведомлений
* Бот запрашивает незакрытые напоминания через `GET /api/v1/payment-occurrences/reminders`.
* После успешной отправки сообщения в Telegram бот мгновенно отправляет запрос `PATCH /api/v1/payment-occurrences/{id}/reminder-sent`.
* Это гарантирует, что при следующем запуске планировщика пользователь не получит дублирующее уведомление.
* Определение новых регулярных платежей отслеживается ботом каждые 3 минуты с сохранением обработанных идентификаторов в локальный файл `seen_payments.json`.

### 3. База данных и миграции
* По умолчанию бэкенд применяет миграции Entity Framework Core автоматически при старте (`Database__MigrateOnStartup=true`).
* Начальный администратор создается автоматически, если заполнены переменные `ADMIN_USERNAME` и `ADMIN_PASSWORD`.

## 🛠 Быстрый запуск всей системы

### 1. Клонирование и настройка секретов
Скопируйте шаблоны `.env` файлов и заполните их необходимыми значениями:

```bash
# Копирование .env для бэкенда/docker
cp .env.example .env

# Копирование .env для фронтенда
cp frontend/.env.example frontend/.env

# Копирование .env для телеграм-бота
cp tgbot/bot-aiogram/.env.example tgbot/bot-aiogram/.env
```

Отредактируйте созданные файлы `.env`, указав единый `BOT_SERVICE_TOKEN`, пароли от СУБД и токен бота от BotFather.

### 2. Запуск через Docker Compose (Backend + PostgreSQL)

```bash
docker compose up -d --build
```
После запуска:
* API Бэкенда и Swagger UI доступны по адресу: `http://localhost:8080/swagger`
* PostgreSQL доступна на порту `5432`

### 3. Запуск Frontend

```bash
cd frontend
npm install
npm run dev
```
Интерфейс будет доступен по адресу: `http://localhost:5173`

### 4. Запуск Telegram Bot

```bash
cd tgbot/bot-aiogram
python -m venv .venv
source .venv/bin/activate  # Для Windows: .venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

Подробные инструкции по тестированию и отдельным видам развертывания см. в папке [`docs/`](./docs).
